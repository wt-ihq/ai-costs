# CLAUDE.md

Internal dashboard for Intent HQ that tracks AI-tool spend (Anthropic, OpenAI, Cursor) by company → team → person, attributing usage to employees via Okta.

## Commands

```bash
npm run dev          # local dev server
npm run build        # production build (run before deploying; CI=true to silence prompts)
npm run lint         # eslint
npm run test         # vitest run (all tests)
npm run test:watch   # vitest watch
```

Always run `npm run test` and `CI=true npm run build` before committing ingest/query changes.

## Stack

Next.js 16 (App Router) · TypeScript · Tailwind v4 · Supabase (Postgres) · Auth.js v5 (Google SSO) · Recharts · Motion. Deployed on Vercel; daily cron at 06:00 UTC.

## Architecture

- **`src/app/(dashboard)/explore/`** — the dashboard: Company → Team (`[team]`) → Person (`[team]/[person]`) drill-down. Server components read via `src/lib/queries/`.
- **`src/lib/queries/`** — read layer. `common.ts:fetchFactsInRange` is the main fact reader; `explore.ts`, `data-health.ts`, `api-platforms.ts` build page data.
- **`src/lib/explore/`** — pure shapers (`shape.ts`) + types for the explore views. Unit-tested.
- **`src/lib/ingest/`** — the write pipeline:
  - `sources/` — live API fetchers (injectable for tests).
  - `normalizers/` — vendor payload → `SpendFact[]`. Fixture-tested; throw `SchemaDriftError` on unexpected shapes.
  - `run-*.ts` — per-source orchestrators; `run-all.ts:runAllSyncs` runs them source-isolated.
  - `persist.ts` — employee resolution + `upsertSpendFacts` + `replaceWindowFacts` (snapshot-replace: upsert first, then prune stale keys — never delete-then-insert).
  - `pricing.ts` — Anthropic token list-price table.
- **`src/app/api/cron/sync/route.ts`** — the sync endpoint (CRON_SECRET-gated, fails closed if the secret is unset). `?from=&to=` overrides the window for backfill; `?source=cursor` (comma-separated) runs a single source. **All sync/delete windows are exclusive-end** (`[startDate, endDate)`), matching the vendor APIs.
- **Auth**: `src/proxy.ts` (edge gate: signed in) + `src/lib/auth-guard.ts:requireDashboardAccess` (page gate) + `requireAdmin` — **every `"use server"` action must call `requireAdmin()` first** (actions are public POST endpoints; the layout gate does not run for them). `AUTH_DISABLED=true` only works with `NODE_ENV=development`.
  - **Dashboard access** (migration `0020_dashboard_access.sql`, applied before deploy): admins (`ADMIN_EMAILS`) always; any other @intenthq.com sign-in only when on `dashboard_access` (Data → Access), else `/no-access`. Each listed person is a `viewer` or an `admin` (`role`, migration `0021`, applied before deploy): **the session's role is ADMIN_EMAILS only — list admins are resolved per request** in `auth-guard.ts:getDashboardAccess` (which `getRole`/`requireAdmin` go through), so role changes apply on the next page load. An unreadable list fails closed (ADMIN_EMAILS admins only). **Every `(dashboard)` page must call `await requireDashboardAccess()` itself** — a layout doesn't re-run on in-app navigation, so it can't guard pages alone; `(dashboard)/pages.test.ts` fails a page that doesn't. The rule (`src/lib/dashboard-access.ts`) also decides Slack digest links: `RenderOpts.links` is **off by default**, and runNotify/test sends turn it on per recipient (preview: the intended recipient, not the previewer). `notification_sends.dashboard_link` records whether a send had the button; the open rate counts only those. Step 2 (people seeing only their own/team's pages) is not built yet.

## Data model

Single `spend_facts` table. Unique key: **`(source, day, cost_type, entity_key, model)`** — `upsertSpendFacts` upserts on this.
- `cost_type`: `seat` | `subscription` | `overage` | `metered`. **`metered` is labelled "API"** in the UI (`COST_TYPE_LABEL` in `src/lib/types.ts`). `overage` = usage-based spend beyond the plan. `subscription` = recurring tool costs materialized from `recurring_costs`; entries can be **vendor-tagged** (e.g. OpenRouter's platform fee) so the facts land under the real vendor and Explore shows one row split subscription vs usage — which is why **every metered sync's `replaceWindowFacts` is scoped `{ costType: "metered" }`** (an unscoped replace would prune the vendor's subscription facts nightly), and `subscription` facts are person-less everywhere (department-attributed; excluded from unmatched queues via `cost_type`, not just `source === "other"`).
- Idempotent: re-running a window upserts the same keys. Metered/snapshot syncs go through `replaceWindowFacts` — no-op on an empty snapshot (a transient empty API response can't wipe a month), and upsert-before-prune so a crash mid-sync leaves stale rows (healed next run) rather than a blank window.
- Employees (from Okta) are the identity spine; facts attribute via `entity_key` (email or owner) → `employee_id`. Roster pages show all employees/departments ($0 if no spend).

## Source-specific notes

- **Anthropic** — hybrid: the **Cost Report API is the authoritative daily total** (its `amount` is in **CENTS** — ÷100; the earlier "~1000× too high" scare was this unit misread, fixed in 38df7bd), and Usage-report tokens priced at list rates (`pricing.ts` → `priceUsageResult`, scaled per day via `estimateAndScale`) provide the per-key/per-model split. Exact total, estimated allocation. Keep the list-price table current — a stale table skews the split even though day totals stay exact. Per-key → creator (`created_by` user → email → employee). Days with cost but no usage rows land as an `unkeyed` fact. **Periodically eyeball totals against Claude's own dashboard** (gotcha #2).
- **Cursor** (Teams plan) — three Admin API endpoints: `teams/members` → authoritative seat roster → one $40 `seat` fact per non-removed member, **current month only** (the roster is date-less, so it's gated to the window's current month; historical months fall back to usage-derived seats); `daily-usage-data` → one $40 seat per member *listed* that month, active or not (covers historical months; a member removed early in a month still gets that month's seat — `normalizers/cursor.ts:normalizeCursor`). The members roster also lists removed people (`isRemoved: true`, skipped); `filtered-usage-events` → **on-demand only**: `chargedCents` of `Usage-based` events, aggregated into `overage` facts per (entity, day, model). **Every event is priced, including plan-included usage** ("Included in Business", often `isChargeable: true` with real `chargedCents`); that usage is covered by the seat, and `/teams/spend` `spendCents` excludes it. Counting it (Jul–Oct 2026) inflated Cursor overage by thousands a month. Known non-billed kinds are skipped; a charged event of an unknown kind throws `SchemaDriftError`. Service-account usage has no email (human events carry the string `"null"` as `serviceAccountId`) and lands under `cursor service account <id>`, a person-less pseudo-entity. Events are fetched and **replaced** (`replaceWindowFacts`, scoped to overage, `pruneWhenEmpty` when Cursor answered with events) in 3-day chunks (`run-cursor.ts:syncCursorEvents`); the nightly run re-reads only the last 3 days (`NIGHTLY_EVENT_DAYS`): a month-to-date fetch overran the 300 s cron and its raw payload failed to save. Data → Sync → "Rebuild Cursor on-demand spend" re-imports a month (`rebuildCursorOverage`). The Data Health reconciliation compares people's on-demand facts with `spendCents`, service accounts shown apart. Fetchers retry 429/5xx with backoff. (Model-usage/MCP analytics require the **Enterprise** plan — gated off via `CURSOR_ANALYTICS_ENABLED`.)
- **OpenAI** — costs endpoint; attributed via project owners. One request per month window, but the org's admin endpoints allow **30 requests/minute shared with other tools in the organisation**: since late Sep 2026 something else polls at 06:00 UTC and the nightly run was refused almost every night (runs at other times succeeded). `sources/openai.ts` waits out 429/5xx (Retry-After, else 10/20/30/60/60 s).
- **OpenRouter** — `POST /analytics/query` (dimensions `["user","model"]` + day granularity; the `date__day` bucket doesn't count against the 2-dimension cap) is the fact source, queried **once per workspace** (`workspace` is allowed as a *filter*, giving workspace × user × model grain): member rows sum org-wide to email entities (→ employee); keyless rows (workspace-owned API keys) become entity_key = workspace name with the department from `openrouter_workspaces` (auto-registered, department **prefilled with the workspace name** — the org names workspaces after departments; admins correct exceptions on Data → Tools). A workspace can also have an **owner** (`openrouter_workspaces.owner_employee_id`, migration `0022`, applied before deploy; set on Data → Tools): its shared-key spend then lands on that person with no fact department, so it follows the owner's own team (`run-openrouter.ts:applyWorkspaceOwners`); setting or clearing it moves the workspace's history in place (`assignOpenRouterWorkspaceOwner`). Falls back to one org-wide query if `/workspaces` fails. Per-day USD + tokens + requests; the first source to populate the `tokens`/`requests` columns. Metric values may arrive as **strings** — parse defensively; a `metadata.truncated` response **throws** rather than persisting a partial window. `GET /activity` (last 30 completed UTC days, exact charged USD) is the drift check — any day it reports more than analytics gets the difference as an `unkeyed` fact. Both need `OPENROUTER_MANAGEMENT_KEY` (a **management key**, Settings → Management Keys — not an inference key, which 403s). BYOK spend (`byok_usage_inference`) is deliberately excluded (would double-count the provider's own facts). Dedicated `/openrouter` page; lifetime sanity check: sum of facts ≤ `GET /credits` `total_usage`.
- **ECB exchange rates** — the nightly sync (`run-ecb.ts`, source `ecb`) reads the ECB's daily reference rates (`eurofxref-daily.xml`, public, euro-based, published ~16:00 CET on working days) and stores **USD per GBP and per EUR** in `fx_rates` with `source = 'ecb'` (migration `0023`, applied before deploy), dated by the ECB's reference date. They only **prefill** rate fields (Imports → Claude Team's £→$, Tools → recurring £/€ costs), labelled "ECB, 16 Oct"; admins can override, and saved months/entries keep their own rate — nothing is re-priced. A missing USD or GBP rate throws rather than store nonsense.
- **ChatGPT Business / Claude Team (manual imports)** — no API; admins paste from the vendor dashboards on the Imports page. Each import is a **monthly snapshot-replace** stamped to the "Month" field's calendar month. **Export a Custom range covering exactly one calendar month** — ChatGPT's 1M/6M/12M presets are *rolling* windows and double-count across months, and the paste carries no dates so nothing downstream can detect it (gotcha #3 applies). Re-importing the same month is always safe (replace). **Data → Imports opens with a checklist of the month's four manual tasks** (`src/lib/imports/checklist.ts`, pure + tested) and ends with the coverage history. Seats count as done only with that month's **invoice seat counts** (`seat_month_entries`); a tier (roster) upload doesn't count, and without counts a month is estimated from Okta-synced members, which misses about half of the ChatGPT workspace. Claude's £ → $ rate is one shared field (`components/imports/fx-rate.tsx`); a saved seat month keeps the rate it was saved with.
- **Okta** (identity spine) — `GET /api/v1/users?search=status pr` (all statuses incl. DEPROVISIONED leavers), SSWS-token auth (`OKTA_ORG_URL` / `OKTA_API_TOKEN`), paginated via `Link` header. Team = the user-profile `department` field. Deprovisioned/suspended → leaver with `leave_date` (row retained). **Only members of the Okta groups "Staff" and "Outsourced Suppliers" are people** (`run-okta.ts:PEOPLE_GROUPS`, `scopeOktaUsers`), plus stored people who have since left (Okta may drop a deactivated account from its groups; they must still be marked as left). A missing, renamed, ambiguous or empty group fails the sync with nothing written, and so does a run that would remove over half the stored accounts (`planOktaRemovals`). **Bot accounts are also skipped by Okta Title** (`normalizers/okta.ts:SKIPPED_OKTA_TITLES`, "AI Orchestration Bot"): they have real company emails, so they'd otherwise count as people (reports, headcounts, rosters). Stored rows for accounts no longer included are deleted (`persist.ts:removeOktaEmployees`) **unless they carry history** — spend, keys, seats, identities, sends (NO ACTION foreign keys) or a digest list (those cascade, so they're checked first). Kept rows are no longer updated; every synced row is stamped `synced_at`, so they're the active Okta rows with an older stamp than the last Okta sync. Replaced HiBob; attribution still joins on email. **Employees are matched by `okta_id` first, then email** (`persist.ts:upsertEmployees`, two passes so okta_id wins across the batch): Okta emails change (a staged account created with a personal address gets the company one on activation), and keying on email alone failed every sync from 29 Jul to 1 Oct 2026.
- **Slack digests** (`src/lib/notify/`, spec `docs/superpowers/specs/2026-09-30-slack-spend-digests-design.md`) — `/api/cron/notify` runs hourly at :30 and DMs each person at **10:30 in their own Slack time zone, working days only** (Monday's daily covers Friday; `schedule.ts:sendDay`/`dueDigests`; zone cached in `slack_users.tz`, **migration `0016_slack_user_tz.sql` must be applied before deploying**). Each run checks who's due and what's already handled (`sendStates`) *before* loading spend data — keep it that way, the cron fires 24×/day. `SLACK_NOTIFY_MODE` off|preview|live (unset = **off**; preview sends every DM to `SLACK_PREVIEW_EMAIL`). Reporting tree = Okta `managerId` stored raw in `employees.manager_ref`, resolved at read time (`tree.ts`) against okta_id/email/employee_number. **Managers of managers** (a direct report with an active report: `tree.ts:seniorBranches`) get a "By team" breakdown in their reports section: one bullet per direct report, "Team · Name (people) $X", largest first, top 6. Data → Notifications' **Reporting lines** panel (`org-tree.ts`, `reporting-lines.tsx`) picks recipients by structure (a branch, the managers below, all managers, senior leaders); people with no manager or in a loop sit apart and never count as managers. `notification_sends` is claim-before-send: never make a row retryable once a DM may have gone out. **Fixed costs (seats & subscriptions) follow an admin setting** (`notification_settings`, migration 0017, applied before deploy): org default **exclude**, overridden per team, then per person (`fixed-costs.ts`); a digest uses the recipient's setting for every section. Included → monthly counts them as posted (must then match Explore's total), daily/weekly get each day's share (cost ÷ days in month); excluded → every cadence is usage only. Claude Team's monthly paste is usage: monthly always, never daily/weekly (`digest.ts:counted`). **Company report** (spec `2026-10-09-company-report-design.md`): a separate DM to the people on `notification_company_recipients` (migration 0019, applied before deploy), on the same schedule — company-wide usage (chart, top teams by Explore's `rankTeams` grouping with "unattributed" apart, top people with "not tied to a person" apart) plus a text-only seats & subscriptions section (daily/weekly as a share of the monthly bill, compared month on month; monthly as posted); it ignores the fixed-costs setting, and a monthly's total equals Explore's company total. **First-message intro** (`intro.ts`): a person's first live message of any kind opens with a short greeting by first name (first word of the Okta name) explaining what they'll get, when, and who to ask (Workplace Tech, linked to #tech-help by channel ID via `slack.com/app_redirect`); it adapts to their cadences, reports (direct vs by team) and dashboard access. "First" = no live send that was sent, is pending, or ended "interrupted" (`NotifyStore.everLive`); preview-only history doesn't count; one per person per run (the personal summary goes first); an unreadable send log means no intros that run. The admin preview shows it; test sends never include it. It opens with a **welcome banner** image (the same for everyone: `chart-image.tsx:renderWelcomeBannerPng`, uploaded like a chart, only with an intro; a failed upload leaves the text). **Slack images use the Intent brand colours** (`notify/brand.ts`: Warm Cream chart surface, Truffle type, Sky Blue accent for graphics only, Coral never — it's the brand's CTA colour); tool colours in charts are the dashboard's (`dimColorFor`, same tool-colour query), drawn full-strength — never faded, since a faded bar turns pastel on Warm Cream and stops matching. `notification_sends.report` (`personal`|`company`) is part of the claim key — every `SendKey` carries it, so a person's two DMs never block each other. Built once per period per run (`run-notify.ts`); its open link lands on `/explore`. `?date=` replays are preview-only. **Opens:** a scheduled DM's "Open in dashboard" button is `/api/digest/open/<send id>` (id in the PATH — sign-in returns to the path only), which stamps `notification_sends.opened_at` (first click only; migration 0018) and redirects to the recipient's Explore page; `claimSend` returns the row id for this. Test sends link straight to the dashboard and aren't tracked. `SLACK_BOT_TOKEN` is read only in `notify/wiring.ts`. **Migration `0015_slack_notifications.sql` must be applied to production BEFORE this code is deployed — `upsertEmployees` writes `manager_ref`/`employee_number`, so the nightly Okta sync fails until the columns exist.**

## Critical gotchas (learned the hard way)

1. **PostgREST caps every `.select()` at 1000 rows.** Any read of `spend_facts` — or of any growing table (`employees` retains Okta leavers forever, `sync_runs` grows daily) — **must paginate** with `.order().range(from, from+999)` in a loop until exhausted, and the ORDER BY needs a **unique tiebreaker** (`.order("day").order("id")`) or page boundaries inside a day can duplicate/skip rows. See `fetchFactsInRange` / `fetchEmployeesAll` for the pattern.
2. **Reconciliation only means something when sources fail independently.** Don't "verify" the DB against the same upstream API the DB was built from. Sanity-check against an independent invariant (e.g. cost ≤ tokens × max list price) or a separate source (Claude's own dashboard).
3. **Backfill on the grain you display (calendar months), not API-convenience windows.** Non-month-aligned windows + per-window scaling caused boundary artifacts. (Cursor is exempt — its events self-date.)
4. **Never delete-then-insert when the insert might be empty.** Treat an empty vendor response as "no update," not "wipe." Use `persist.ts:replaceWindowFacts`, which also upserts before pruning so a crash mid-sync can't blank a window, and deletes with `.lt(endDate)` (windows are exclusive-end — `.lte` once wiped a day the fetch never covered).
5. **Vendor list endpoints paginate too.** Anthropic Admin lists (`api_keys`, `users`) page with `has_more`/`last_id`; a bare `?limit=100` silently truncates and attribution degrades to "Unmatched". Follow pages, and throw (don't return partial data) when a page cap is hit.

## Conventions & constraints

- Secrets live **only** in Vercel env (never in the DB, client, or git). `vercel env pull` returns empty for sensitive vars — to inspect prod data, use a temporary `CRON_SECRET`-gated route under `src/app/api/debug/`, then delete it.
- **PII:** `reports/` (HR-adjacent samples) is gitignored — local use only. Production `spend_facts` PII reads are restricted; debug routes should return aggregates, not per-person rows.
- **Deploy only when the user asks.** Branch off `main`; commit/push only when requested.
- Production-DB deletes require explicit per-action user authorization (the auto-mode classifier blocks agent-initiated ones).
- New server actions **must** start with `await requireAdmin()` (`src/lib/auth-guard.ts`); new cron/debug routes gate through `src/lib/cron-auth.ts:isCronAuthorized` (fails closed).
- When shipping user-visible changes, add a plain-language entry (features and fixes, no jargon) to `CHANGELOG` in `src/lib/changelog.ts`, newest first — it feeds the "What's new" popover.
- **Cache layer** (`src/lib/queries/cached.ts` — heavy reads cached via `unstable_cache` under `FACTS_TAG`, hourly safety revalidate). Two separate invariants:
  - *Write paths:* any new server action or route writing `spend_facts`, `employees`, `seat_month_entries`, `recurring_costs`, `vercel_projects`, or `seat_assignments` must bust the tag — `updateTag(FACTS_TAG)` in Server Actions (read-your-own-writes), `revalidateTag(FACTS_TAG, "max")` in route handlers like the cron. This Next 16 build **requires** the second profile arg on `revalidateTag`; the one-arg form is `updateTag`, Server-Action-only. Otherwise admins see stale data for up to an hour. New heavy reads belong in `cached.ts`, not fetched raw in pages.
  - *Shape changes:* changing the shape of anything a `*Cached` reader returns — **adding a field counts** — MUST bump `CACHE_VERSION` in the same commit. Cache entries survive deploys, so the new build reads old-shaped entries and the page throws on every cache **HIT**. Tests, lint and `CI=true npm run build` all pass regardless (the stale entry exists only in prod), so this is a checklist item, not something testing catches. Versioning exists *because* this crashed once already (c82bb34, `unpackScope` on packed scopes, introduced at v2) and it crashed again when the rule was forgotten (8f2eac7 → v5). The bumps that went right — b105d96 → v3, ce1837d → v4 — were made in the same commit as the shape change. Do that.
- Commit messages end with: `Co-Authored-By: Claude <model name> (1M context) <noreply@anthropic.com>` — use the model actually doing the work (e.g. `Claude Opus 5 (1M context)`), not whichever version this line was last updated for.
